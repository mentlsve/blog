At the start of building a system there is seldomly a detailed specification of what needs to be build but rather a coarse-grained idea for a problem. So you might be either presented with a problem or already a coarse-grained idea.

In case of a coarse-grained idea it is important to go one step back and understand the problem because being presented with one coarse-grained idea already steers you in a certain direction based on assumptions which are unknown to you but relevant to design a good solution.

Start with the use case collection. Who is using the system in order to achieve what. During that step you discover the domain.
